2. Bugs found and fixed

B1. Profile edits were impossible for every real user high

The "Users can update own profile" policy compared subscription_expires_at with = against the existing row. That column is NULL for everyone who hasn't paid, and in SQL NULL = NULL is not true, so the WITH CHECK never passed. Every client-side update to the users table failed with "new row violates row-level security policy". The Settings page also swallowed the error and stayed in edit mode.

Fix: migration 20260923000001_fix_users_update_policy_null_expiry.sql, applied to DEV and PROD. Settings now shows the error text under the field if a save fails.

B2. Results ignored "Other Monthly Income" medium

The Expenses-step preview counted the $100 other income (cash flow −$134) but the Results step, Compare and the shared page did not (−$234). calculateCashFlow() in the calculations package now takes an optional other-income argument that is added to gross income without vacancy, and all three callers pass it. Two unit tests added.

B3. Dollar-mode management fee produced a nonsense percent medium

Entering a fixed $150/mo fee stored propertyManagementPercent = 54.55. The toggle field annualised the dollar amount but divided by a monthly base. That bogus percent then leaked into the detail page, the shared page, the Compare row and the multi-year projections. Fixes:

  • Wizard now computes the percent against annual gross income (4.55% for the same input).
  • Projections honour dollar mode and grow the fixed fee with the expense-increase rate. Two unit tests added.
  • Detail, shared and Compare views display "$150/mo" when the mode is dollar instead of the percent.
  • The shared page's own cash-flow computation is now mode-aware.

Rows saved before this fix keep the bogus percent in the database. Re-saving from the wizard corrects them. Only the QA rows on DEV are affected today.

B4. "Upgrade to Pro" banner still in the sidebar low

Missed in the open-beta cleanup. Removed.

B5. Settings save failed silently low

Covered with B1: an error line now appears under the name field.

B6. Utilities missing from the Results expense list low, not fixed

The First Year tab lists tax, insurance, maintenance and management but not utilities or other expenses, while "Total Operating" includes them. Numbers are right, the itemisation is incomplete. Left for a later UI pass.

3. Observations, not bugs

  • The header always says "Dashboard" regardless of page. Cosmetic.
  • Gross rent renders as "$3200.00" without a thousands separator on the Results tab.
  • The "Complete" button on the Results step is permanently disabled and has no visible purpose.
  • A share link's view count starts at 1 before anyone opens it.
  • The "Debug: Form Values" panel under the calculator is development-only and does not ship.
  • The Compare "Mgmt Fee" cell renders "$150/Mo" because the column uses CSS capitalize.

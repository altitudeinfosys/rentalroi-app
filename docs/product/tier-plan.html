RentalROI tier plan

Record of the original Free/Pro split, what the code actually enforced, the open-beta decision, and how a paid tier comes back. Decided 2026-09-22.

Current state: open beta, everything free. No caps are enforced anywhere. The tier columns, functions and counters stay in the database so a paid plan can be switched on later without a schema redesign.

What was deliberately kept

  • users.subscription_tier enum column (free / pro / premium) and the RevenueCat columns.
  • get_user_tier() and get_calculations_this_month() SQL functions.
  • The trigger that increments calculations_this_month on every save and resets it monthly. Usage keeps being counted even though nothing reads it, which gives real numbers to set future limits from.
  • The "Service role can manage users" policy, which is how a billing webhook will set the tier.

4. Plan for bringing a paid tier back

Principle: keep single-property analysis free forever. Charge for portfolio scale and for anything that costs money per use.

Implementation order when the time comes

  1. Stripe Checkout + Customer Portal, one Pro price. Webhook writes subscription_tier and subscription_expires_at via the service role.
  2. Migration restoring tier checks in RLS with the chosen numbers.
  3. Bring back the two-card pricing section and the Settings usage meter, reading limits from one shared constant so the client, pricing copy and database can't drift again.
  4. Grandfather beta users: everything they saved stays readable regardless of tier.

5. How to restore the old policies

The original policy definitions are in supabase/migrations/20260126000002_rls_policies.sql (lines 131 to 147 for calculations, 179 to 191 for projections, 238 to 256 for shared links). A future migration should drop the open-beta policies by name and recreate those with updated numbers:

DROP POLICY IF EXISTS "Users can create own calculations" ON calculations;
CREATE POLICY "Tier enforcement for calculation creation" ON calculations
  FOR INSERT WITH CHECK (
    auth.uid() = user_id AND (
      get_user_tier() IN ('pro', 'premium')
      OR (get_user_tier() = 'free' AND get_calculations_this_month() < <new limit>)
    )
  );
